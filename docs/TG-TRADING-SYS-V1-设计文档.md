## 1. 系统概述

**TG-TRADING-SYS-V1** 是一套全A股（北交所除外）日频综合分析决策系统。核心逻辑：原始数据 → 逐层加工 → 结构化中间指标 → 交叉组合 → 多维分析应用。

### 1.1 与现有 V4.0 的关系

| 项目 | V4.0（现有） | V1（新系统） |
|------|-------------|-------------|
| 定位 | 选股管线 + 组合 + 风控 | 全市场综合分析 + 多维应用 |
| 估值 | DCF/PEG/PB-ROE/研报 ✅ | **复用并增强**：新增行业估值对比、自历史对比 |
| 量价 | 无 | **复用** `功能模块代码/量价分析/` VPA引擎 |
| 技术面 | 19因子 + 择时 | **新建**：全市场技术指标 + 信号标注 |
| 资金流 | 无 | **新建**：四维资金分析 |
| 筹码 | 无 | **新建**：Tushare cyq系列 |
| 情绪 | 无 | **新建**：综合情绪指标 |
| 缠论 | czsc已安装，scripts/有示例 | **新建**：全量自动化分析 |
| 数据库 | `tg_trading.db` | **独立新库** `tg_trading_v1.db` |

**原则**：V1 复用 V4.0 的估值引擎（DCF/WACC/PEG/PB-ROE/研报共识）、VPA量价引擎、数据缓存模式；数据库独立建库，避免与 V4.0 相互影响。

### 1.2 覆盖范围

- **市场**：全A股（沪深主板 + 创业板 + 科创板），不含北交所
- **指数**：上证指数、深证成指、创业板指、科创50、沪深300、中证500、中证1000
- **频次**：日频为主（部分模块支持5分钟/30分钟级别）
- **数据截止**：每日收盘后运行（T+0日18:00后）

```
┌─────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────┤

│  估值  │  技术面  │  量价关系  │  资金流向  │  筹码  │  情绪  │  缠论  │
├─────────────────────────────────────────────────────────────┤
│                    第二层：数据汇总层                          │
│  日K线汇总  │  分钟K线汇总  │  财报汇总  │  行业映射  │  研报汇总  │
├─────────────────────────────────────────────────────────────┤
│                    第一层：数据及基础技能层                      │
│  Tushare │ mootdx │ 腾讯 │ 东财 │ 同花顺 │ 新浪 │ 巨潮 │ czsc │
│  SKILL.md 41端点  │  vibe-trading因子库  │  VPA引擎  │  V4.0估值  │
└─────────────────────────────────────────────────────────────┘
```

**数据流**：
1. L1 适配器拉取原始数据 → 写入临时/源表
2. L2 按日汇总清洗 → 写入统一格式的中间表
3. L3 七模块并行计算 → 写入 `stock_daily_snapshot` 及各模块子表
4. L4 读取L3输出 → 交叉组合 → 生成报告/HTML/数据库视图

**调度原则**：
- L3 模块间依赖最小化：估值/技术面/量价/资金流/筹码/缠论 可并行
- 市场情绪 依赖 量价 + 资金流的部分输出，排在最后
- 每模块内部支持增量更新：仅计算有变化的数据

### 5.3 增量更新策略

```
每日运行流程：
1. 检查 trade_date 最新记录
2. 拉取新交易日数据
3. 财报季度切换时（4/30, 8/31, 10/31, 4/30前），自动拉取最新季度财报

5. 标记 data_fresh = 1 供 L3 消费

## 6. 第三层：数据指标汇总计算层

### 6.1 估值板块

#### 6.1.1 估值方法（4种 × 自适应权重）

**核心代码基础**：复用 `TG_trading_sys/valuation/` 中已验证的函数。

| 方法 | 权重(有研报) | 权重(无研报) | 核心逻辑 | 代码来源 |
|------|------------|------------|---------|---------|
| **PEG** | 40% | 60% | Fair PE = EPS CAGR × 1.0；Fair Value = Fair PE × trailing EPS | `relative_val.py:peg_value()` |
| **研报综合** | 30% | - | 所有覆盖研报目标价取中位数；若无目标价则用EPS×行业PE反算 | `relative_val.py:_research_consensus()` |
| **DCF** | 15% | 20% | 两阶段DCF，WACC通过CAPM+回归估算 | `dcf.py:dcf_value()` |
| **PB-ROE** | 15% | 20% | Fair PB = (ROE-g)/(Ke-g)，下限0.5 | `relative_val.py:pb_roe_value()` |

**特殊规则**：
- 金融股（银行/保险/券商）：PB-ROE权重翻倍（替换PEG的一半），DCF禁用（金融股FCF无意义）
- 亏损股（EPS ≤ 0）：PEG不可用，权重重新分配为 DCF 40% + PB-ROE 60%（有研报则研报20%+DCF40%+PB40%）

#### 6.1.2 估值比较维度

**维度一：自历史比较**
- 计算当前综合估值在过去1年/3年的分位
- 指标：`vs_history_pct`（当前估值处于历史多少分位）
- 分位越低 → 越低估
- 使用 `stock_daily_snapshot` 历史记录计算

**维度二：行业比较**
- 按Tushare行业分类 + 细分板块
- 行业内按市值加权平均
- 指标：`vs_industry_pct`（当前个股估值处于行业多少分位）
- 分位越低 → 相对行业越低估

#### 6.1.3 行业分类体系：申万 SW2021

**采用申万 SW2021 三级分类**（Tushare `index_member_all`，2000积分）：

| 层级 | 数量 | 用途 |
|------|------|------|
| L1（一级行业） | 31 | 行业估值总览、大类轮动 |
| L2（二级行业） | 134 | 细分板块分析、行业排名 |
| L3（三级行业） | 346 | 精细同行对比、因子中性化 |

**数据维护**：首次全量拉取 `index_member_all(is_new='Y')` → 本地字典缓存 → 定期（月度）检查成分变动。个股映射通过 `stock_basic` → `index_member_all` 双向关联。

#### 6.1.4 行业估值计算

按 SW2021 三级分别计算：

```
对每个(行业层级, 行业名称, 交易日)：
  1. 选出该行业所有股票当日的 composite_value
  2. 按个股自由流通市值加权平均  → weighted_avg_valuation
  3. 取中位数 → median_valuation
  4. 计算行业平均PE(加权)、PB(加权)
  5. 写入 industry_valuation 表

支持按 L1/L2/L3 任意粒度汇总查询。
```

#### 6.1.5 增量更新逻辑

```
每日触发检查：
1. 股价变动 → 影响：PEG(仅重算fair_value)、PB-ROE(仅重算fair_value)、行业权重
2. 财报更新 → 影响：PEG(EPS CAGR)、DCF(FCF/增长假设)、PB-ROE(ROE/NAV)
3. 新研报 → 影响：研报综合估值
4. 无变化项 → 跳过重算，沿用上期值

运行策略：
- 每日：轻量级更新（股价相关）
- 财报触发：全量重算该股所有估值
- 研报触发：仅重算研报综合 + 综合估值
```

#### 6.4.5 进阶量化因子算法

**主买成交特异性因子**（Active-Buy Concentration）：
```
对每只股票每日：
  主动买入额 = sum(买入成交额 where 买单方向='主动')
  主动卖出额 = sum(卖出成交额 where 卖单方向='主动')
  
  特异性 = (主动买入额 / 成交总额 - 0.5) × 2  # 标准化到[-1,1]
  集中度 = std(各分钟主动买入额) / mean(各分钟主动买入额)  # 变异系数
  
  因子值 = 特异性 × 集中度  # 高值 = 买入集中流入
```

> **数据依赖**：分钟级成交方向数据。Tushare `moneyflow` 仅有日级汇总，分钟级需 mootdx 逐笔数据估算。**MVP阶段可暂用日级近似**（大单买入额/成交额替代），后续版本升级。

**虹吸效应因子**（Siphon Effect）：
```
对每只股票每日：
  net_sell_3d = 近3日累计净卖出（正值为流出）
  虹吸潜力 = net_sell_3d / 近20日均成交额  # 流出越多，回流潜力越大
  
  触发条件：当日净买入 > 0 且 虹吸潜力 > 1.5%
  因子值 = 虹吸潜力 × (当日净买入/成交额)
```

**引力场因子** = (主买特异性 + 虹吸效应) / 2

```

情绪定性：
  [-100, -60)：极度悲观
  [-60, -20)：悲观
  [-20, +20]：中性
  (+20, +60]：乐观
  (+60, +100]：极度乐观

## 7. 第四层：分析应用层

### 7.1 决策森林选股系统

#### 7.1.1 定位

短周期（持股 **3-15个交易日**）的综合性选股系统。找到：

> 估值被市场相对低估 + 技术面调整相对完备 + 量价配合 + 有资金介入 + 情绪在好转 + 趋势在形成或运行中

#### 7.1.2 选股因子与权重（可调参）

因子权重**支持机器学习+回测动态优化**，非固定值。初始默认权重如下，作为调参起点：

| 维度 | 因子 | 默认权重 | 调参范围 | 取自L3模块 |

### 7.3 趋势分析

#### 7.3.1 三级四窗口

> **用户明确需求**：5分钟K线看5天，30分钟K线看10天，日线看20天。

| K线级别 | 分析窗口（K线数） | 约合自然日 |
|---------|-----------------|-----------|
| 5分钟 | 最近240根 | ~5个交易日 |
| 30分钟 | 最近80根 | ~10个交易日 |
| 日线 | 最近20根 | ~20个交易日（约1个月） |

对每个标的（指数/板块/个股），在每个级别输出**趋势状态**：

#### 7.3.2 趋势判定算法

```
趋势判定（对级别×窗口的K线序列）：
  
1. 均线斜率法：
   MA20斜率 > 0.5%/日 → 上升趋势
   MA20斜率 < -0.5%/日 → 下降趋势
   否则 → 横盘

2. 高低点法：
   近窗口内高点上移+低点上移 → 上升趋势（更高高点+更高低点）
   近窗口内高点下移+低点下移 → 下降趋势（更低高点+更低低点）
   否则 → 横盘

3. 趋势强度 = |MA20斜率| × 趋势持续性（窗口内同向K线占比）

综合判定：
  - 方法1+2都判上升 → "上升趋势"
  - 方法1+2都判下降 → "下降趋势"
  - 一方判上升一方横盘 → "偏多震荡"
  - 一方判下降一方横盘 → "偏空震荡"
  - 都判横盘 → "横盘整理"
  - 矛盾（一上一下）→ "方向分歧"（标记需人工判断）
```

#### 7.3.3 三级趋势共振判定

```
共振矩阵：
                    日线趋势
              ↑       →       ↓
30分  ↑   强共振多   偏多     分歧
钟趋  →   偏多      横盘     偏空
势    ↓   分歧      偏空    强共振空

5分钟趋势同理与30分钟比较。

完全共振（三级同向）= 最高置信度信号
```

#### 7.3.4 输出规格

- 每只股票 × 每日 = 三级趋势状态 + 共振判定
- 指数趋势单独输出（HTML图表 + JSON）
- 重点标注"完全共振"的股票（决策森林加分项）
